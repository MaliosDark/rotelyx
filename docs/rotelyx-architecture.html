Protocol

Peer to peer messaging and calling with its own codec and its own media transport, message encryption that survives a compromised server and a compromised relay, and a store and forward layer whose operator is told a tag and a padded blob and nothing else.

Built · verified by test, not by assertion

What runs today

Every claim below is backed by a test that fails if the claim stops holding. The interesting part is not the count. It is that the unit tests all passed while four real defects sat underneath them, and only tests crossing a layer boundary, using real sockets, or running between two independent implementations found those.

Access control, room acoustics, the terminal client and the relay account for the remaining 80 of the 589.

Four clients run the same stack and they do not offer identical guarantees. The phone links the engine into its own process through a C ABI. The desktop window keeps plaintext inside one process. The browser build carries it across loopback, which admits anything on the machine that can reach that port, and says so in its own interface. The terminal client holds everything in one process. A project that ships several clients and describes them all with one security claim is making a false statement about at least one of them.

Found by testing

MLS was not padding at all

Overhead is a constant 145 bytes and the rest is one to one, so plaintext length leaked exactly. Worst on the direct path, where there is no envelope to hide behind and this was the only length defence.

Found by testing

Dropped streams discarded data

A QUIC send stream dropped without finishing resets and silently discards data the sender believes was delivered. Write then drop is the obvious pattern; it lost the last message of every session with no error anywhere.

Found by testing

A failure shaped like a normal condition

A media frame that cannot be decoded is concealed rather than counted, which is right for packet loss and hides a corrupted payload completely. One call ran with eleven usable frames out of three thousand and every layer reported it healthy.

How a message travels

Five layers, and two of them encrypt

The two encryption layers are independent by construction: no key material is derived from one into the other, so a break in either leaves the other intact. That is a design rule enforced by keeping the derivation inputs disjoint, not a coincidence of the implementation.

Post quantum

At a point the standard already defines

RFC 9420 defines seven ciphersuites and all of them are classical, so a conversation recorded today is decryptable by a future adversary with a quantum computer. Rotelyx does not fork MLS to fix that. It injects a hybrid secret at the pre shared key input, carried as a proposal inside a commit.

Why here

The analysis survives

MLS has machine checked symbolic security analysis. Any modification to the protocol forfeits the benefit of it. Injecting at a defined extension point does not, and two properties come free: the material refreshes every epoch, and no member can inject a chosen key silently, because the proposal is part of a commit every member validates.

Reviewable

Forty lines, and vectors to check them

The composition is the single novel cryptographic construction in the system and is small enough to read in an afternoon. Test vectors are published beside a written specification and checked against the implementation on every test run, so reproducing our output from the document is possible without reading our source.

How we know it is real

A negative test

The injection function was once written, compiled and covered by passing tests while being dead code: it emitted commits no receiver could apply. What proves the layer is load bearing is a test asserting that a commit carrying the proposal fails for a member that has not staged the secret.

Path selection

The objective function is inverted on purpose

Peer to peer transports try a direct hole punched path and fall back to a relay when traversal fails, then choose among available paths by round trip time. Roughly one NAT pair in five cannot be punched, so the fallback is not rare and the choice is not academic.

Three policies exist. PreferDirect is the default and takes any direct path over any relayed path at any latency. DirectOnceAvailable additionally refuses to return to a relay once a direct path has been established, accepting connection failure as the outcome if that path dies. Fastest reproduces the ordinary objective and exists so the other two have a measurable baseline.

The refusal for calls is in the media layer rather than in a caller that could forget it. The same audit found the address itself leaking: the string a user pastes is built from whatever the endpoint knows about reaching itself, which on an ordinary machine is its IP and port, and it travelled even on relay only sessions. A relay only address now carries the relay and nothing else.

The blind mailbox

Everything the operator holds

Direct delivery needs both peers online, which on a phone is the exception, so a store and forward component is unavoidable. The design goal is to make its operator’s knowledge as close to nothing as routing permits.

Design decision

Collection is destructive

An envelope handed over is gone, so a client that crashes mid collection loses those messages. The alternative is a mailbox that keeps copies, which is the property being designed against.

Design decision

Groups fan out on the server

Every member has its own tag, or one shared tag would be collected by whoever reached it first and the rest would never see the message. One copy per member is unusable on a phone if the client uploads each, so the sender uploads once and names every recipient.

Not enforced by the protocol

Deletion is a promise

A hostile operator can retain everything and no client can detect it. The mitigation is structural rather than cryptographic: the mailbox is a single self hostable binary, so compromising one operator compromises one community rather than a population.

First contact

Meeting somebody without an address

The mailbox delivers only to people who already share a conversation. First contact needs something else, and on a phone the usual answer does not exist: an invitation carries a public key and has to be delivered to an address, and a phone has no listening socket, moves between networks and is asleep most of the time.

A meeting code is 120 random bits written as 29 characters after an RTLX1 prefix. It carries no key. Both sides run the canonical form through the same derivation, arrive at the same tag, and hand each other the real keys there, where their size costs nothing.

StepWhoWhat is deposited at the meeting tag
1The side that read the codeA key package
2The side that showed itA welcome, and the hybrid ciphertext
3BothNothing more. Addressing moves to the group’s own tag and the meeting place is abandoned

Everything at a meeting tag is visible to the operator, and that is by construction rather than by accident: a key package is public, a welcome is encrypted to the joiner’s own key, and the hybrid ciphertext is encapsulated to their public key. Nothing at a meeting place is a message.

The code cannot be the invitation itself. A post quantum public key is 1216 bytes, which puts an invitation at roughly three thousand characters against a QR ceiling of 1273 at the correction level that leaves room for a mark in the middle. Naming a place costs 29 characters.

What a code costs

One attempt at being first

A code is not proof of who is holding it. Whoever reaches the tag before the intended person completes the handshake in their place, and nothing in the implementation prevents it. Comparing the safety number is the only thing that detects it, which is why it is on screen from the moment the conversation exists.

Consequence

A conversation with yourself is a group of two

The tag key comes from the group’s exporter secret and a group of one has no secret to export, so a solo group has no address at all. The client joins the same device twice instead, and to the mailbox that is two members with nothing special cased.

Deliverability

Tags rotate, polling overlaps

Tags are derived per hour and each side also polls the preceding windows, so an envelope deposited a minute before a boundary is still collected after it. The same derivation is implemented in Rust and in Dart, and each mints a code the other reads.

Voice

Our own codec, our own media transport

An MLS application message is ordered, reliable and ratcheted. Audio is the opposite: frames arrive every twenty milliseconds, some never arrive, and a late frame is worthless rather than worth waiting for. Media therefore takes a key from MLS and does its own framing.

PropertyHow it works
KeysOne per speaker, derived from the group’s exported media key and that participant’s identity. Counters cannot collide, and a frame claiming to be from one member can only have been produced by that member
RekeyingThe key changes with the epoch, so a membership change rekeys the call and a removed member stops being able to decrypt immediately rather than at the end of it
Frame20 ms, 960 samples at 48 kHz, 60 bytes on the wire at 24 kbit/s. A 40 ms transform window over a 20 ms hop, Bark spaced bands, energy coded separately from shape
LayersA base and three refinements in one datagram. Splitting them across datagrams puts more on the wire than the stream carries, because the authentication tag is most of a packet this small
PathRelay only, refused otherwise

A phone and a desktop have called each other, in both directions, over the relay. Four faults stood in the way and not one was visible from either end: a QUIC stream opened and never written to, an address published before the relay had registered the endpoint behind it, two clients encoding different frame formats, and a capture buffer read from the start of a platform channel’s whole reply rather than from the start of the window onto it. The last one sent the reply’s header out as audio, perfectly delivered.

None of it produced an error, because a frame that cannot be decoded is concealed rather than counted. Concealment is now reported beside the received count, and the tools that found the fault stay in the tree: a recording of what the speaker played, a recording of each payload as it arrived, and an offline decoder that replays both away from the call.

Reachability

Free identities mean free spam. Scarcity is the only answer.

Removing telephone numbers removes the natural scarcity that limits bulk unsolicited contact. Cryptography does not address this. Only two forms of scarcity are available: authorisation, and cost.

Authorisation is the default. An identity is unreachable unless the caller holds an invitation it issued out of band. The caller proves possession with a MAC over its own identity and the current hour, checked against the identity the handshake already authenticated, so an observed proof cannot be replayed by a different caller without also stealing that caller’s private key. Revocation is surgical: revoking a leaked invitation does not affect holders of others.

Cost is opt in. An identity that must accept strangers can require a proof of work bound to the sender, the recipient and the hour. Each binding removes a reuse strategy: solving once and spending it across an address book, solving once and reusing across throwaway identities, and stockpiling proofs in advance. The blocklist is consulted before any verification work, because a block that still consumes CPU is a block the blocked party can exploit.

Relay admission boundValueWhy this and not something else

A refusal is indistinguishable from any other closed connection, and the counts go to the operator’s log rather than to the public status page. A relay that explained itself would be an oracle for its own policy, and a live count of open connections is a load signal that on a small relay correlates with who is talking.

At rest

What is written to disk, and under what

Identity keys are sealed with Argon2id at 64 MiB and three passes, and XChaCha20-Poly1305 with the file header bound as associated data. Group state and transcripts are sealed under the same construction, because an identity behind a passphrase beside a conversation in the clear makes the passphrase a decoration. On a phone there is also a mode that writes nothing down at all and asks again next time.

A file is a copy, and a copy that resumes sending is sending at generations the other side has already spent. A restored session is therefore marked as needing a rekey and refuses to send until it has committed a fresh epoch. That also covers the case a browser cannot distinguish from an ordinary reload: the same sealed blob opened on a second device.

Two limits remain. The sealing key comes from a passphrase rather than from a platform keystore, so its strength is whatever the person chose. And the rekey is not reachable from every client yet.

The honest boundary

What this does not defend against

A threat model that lists only solved problems is marketing. These are unsolved, and at least one is unsolvable within the current architecture.

Not protected

A compromised device

A device that renders plaintext to a screen can have that plaintext taken. Nothing on any server helps with a phone that has already been taken over.

Not protected

A global passive adversary

An adversary observing the whole network correlates flows by timing and volume regardless of what any single message contains.

Unsolved

Statistical disclosure

The attack that breaks Signal’s sealed sender applies here too. Tags rotate hourly rather than per message, which gives an operator a clustering key. Read receipts exist and are off by default and per conversation, because turning them on reinstates exactly the amplification the published attack relies on.

Inherent

Relay observation

A relay carrying a session necessarily learns which endpoint talks to which. Path selection minimises how often one is used and self hosting changes who holds the observation. Neither eliminates it, and relay chaining is not implemented.

Inherent

Push notification metadata

Mobile platforms will not permit a background socket, so a platform push service observes that a device woke and when. Content free pushes on one schedule shared by every device raise the cost of correlating a wake with a deposit. None of it solves the problem.

Not yet

Independent audit

There has not been one. Rotelyx is pre release and makes no security claim that should be relied upon until that review is complete.

What is not built

01

Echo cancellation that works in a room

It is written and it removes 38.3 dB against a path this project generated and -0.0 dB against a real speaker and a real microphone. A residual suppressor brings that to 1.3 dB. On a desktop, calls are for headsets; on Android the platform’s own canceller carries it, which makes the property the operating system’s rather than ours.

measured, weak
02

A perceptual measurement of the codec

Every figure recorded is objective, and codec quality is not. Two listening sessions have run and what they established is that the measurement itself was broken: the rating scale was never shown to either listener.

blocked on method
03

Congestion control, and group calls above a handful

Group calls need a unit that forwards streams. The frame header is authenticated but not encrypted and can be routed by without being read, which suits one. What such a unit sees is who is speaking and when, and that should be declared before anyone builds on it.

not started
04

Mitigations for statistical disclosure

Per message tags with a recipient side scan, randomised collection delays, decoy deposits. Each costs bandwidth, battery or latency, and none has been implemented or evaluated.

unsolved
05

iOS, and a keystore backed sealing key

The iOS platform layer is written and has never been through a compiler. The sealing key still comes from a passphrase rather than from the platform keystore.
