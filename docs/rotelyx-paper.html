Rotelyx: Metadata Resistant Messaging on a Peer to Peer Transport

A layered protocol combining MLS group encryption, a hybrid post quantum key agreement, and a blind store and forward mailbox, with an explicit account of what it does not protect.

Andryu Schittone (Malios Dark) Ideoa Labs 20 August 2026 Revision 2
Status: unaudited. This report describes a working implementation that has not undergone independent cryptographic review. No security claim made here should be relied upon until that review is complete. The limitations in section 9 are not hypothetical; several are unsolved.

Abstract

Modern end to end encrypted messengers protect message content well and message metadata poorly. The identity of who communicates with whom, at what times, and at what message sizes, remains visible to service operators and frequently to network observers. This report describes Rotelyx, a protocol that treats metadata minimisation as a first class design constraint rather than an afterthought.

Rotelyx makes three contributions. First, it composes a hybrid post quantum key encapsulation mechanism with the Messaging Layer Security standard (RFC 9420) through the pre shared key input the standard already defines, obtaining post quantum epoch keys without modifying MLS. Second, it inverts the objective function of peer to peer path selection, preferring any direct network path over any relayed path regardless of latency, on the grounds that a relay operator learns the communication graph. Third, it specifies a store and forward mailbox whose operator observes only an opaque rotating tag and a payload of one of five fixed sizes.

We report measured characteristics of the implementation, including a constant 145 byte MLS ciphertext overhead that made an initial padding scheme ineffective, and we analyse the protocol against known traffic analysis results. We conclude that the mailbox design remains vulnerable to the class of statistical disclosure attacks that break Signal's sealed sender, and we state the conditions under which that vulnerability applies.

Introduction

The deployment of the Signal protocol across WhatsApp, Signal, and Google Messages made end to end message confidentiality ordinary. It did not make metadata privacy ordinary. A service operator running any of those systems observes which accounts exchange messages, when, and how large those messages are, and in the common case those accounts are bound to telephone numbers.

This is not an implementation oversight. Metadata is what routing requires. A system that delivers a message must know where to deliver it, and the engineering question is how little it can be made to know while still functioning. Rotelyx is an attempt to push that boundary in three specific places: the identity layer, the transport path, and the store and forward layer.

Design principles

Three rules governed the implementation, and each was violated at least once during development before being caught by a test.

Do not invent cryptography. Group and message encryption is MLS via OpenMLS. The post quantum component is X-Wing. The single novel construction is the composition of the two, and it is approximately forty lines. The failure modes of hand written ratchets are not algebraic. They are nonce reuse under concurrency, state rollback after a backup restore, unbounded skipped key retention, and replay across device re registration. A specification prevents none of them; a widely reviewed implementation mostly does.

Enforce guarantees structurally, not by configuration. A wrong configuration value is discovered in production. A missing constructor is discovered at compile time. Where a guarantee could be expressed as the absence of an enum variant, it was.

State the boundary. Every claim in this report has a matching statement of what it does not cover. A threat model that lists only solved problems is marketing.

The honest boundary

Rotelyx provides no protection against a compromised endpoint and no protection against a global passive adversary. A device that renders plaintext to a screen can have that plaintext taken. An adversary that observes the whole network can correlate flows by timing and volume regardless of what any single message contains. Users at risk from either class need different tools.

Architecture

Rotelyx is organised into five layers. The two encryption layers are independent by construction: no key material is derived from one into the other, so a break in either leaves the other intact.

Post quantum composition

RFC 9420 defines seven ciphersuites, all of them classical.[1] Post quantum ciphersuites for MLS remain in draft. A conversation recorded today is therefore decryptable by a future adversary with a cryptographically relevant quantum computer, an attack pattern usually called harvest now, decrypt later.

Choice of primitive

Rotelyx does not construct a key encapsulation combiner. It uses X-Wing,[2][3] a hybrid KEM built from ML-KEM-768 and X25519 whose security claim is that the shared secret is secure if SHA3 is secure and either X25519 or ML-KEM-768 is secure. Both would need to fail simultaneously for the output to be compromised.

Injection into the MLS key schedule

The contribution of this work is the composition, not the primitive. Rather than forking MLS to add a post quantum ciphersuite, Rotelyx injects the hybrid secret at the pre shared key input that RFC 9420 already defines, carried as a PreSharedKeyProposal inside a commit.

Why this is a small contribution on purpose

MLS has received machine checked symbolic security analysis, both for TreeKEM[4] and for the external operations introduced in RFC 9420.[5] Any modification to the protocol forfeits the benefit of that analysis. Injecting at a defined extension point does not.

Review target

The composition is approximately forty lines of code. It is the single novel cryptographic construction in the system, and it is deliberately small enough to be reviewed in an afternoon. Test vectors for it are an open item, listed in section 10.

Verification that the layer is load bearing

During development the injection function was written, compiled, and covered by tests that passed while the function was in fact dead code: it emitted commits no receiver could apply, because the receiving side had no way to stage the secret locally. The defect was invisible because no test exercised the full path.

The implementation now includes a test asserting that a commit carrying the proposal fails for a member that has not staged the secret. That negative test is what demonstrates the post quantum layer is load bearing rather than decorative.

Metadata resistant path selection

Peer to peer transports attempt a direct hole punched path and fall back to a relay when NAT traversal fails. Approximately 10 to 20 percent of NAT pairs on the public internet cannot be punched, so the fallback is not rare.

The upstream transport selects among available paths by biased round trip time, treating relayed paths as a lower tier but breaking ties by latency. Rotelyx replaces the objective function entirely.

Three policies are exposed. PreferDirect is the default and selects any direct path over any relayed path at any latency, falling back to a relay only when no direct path exists. DirectOnceAvailable additionally refuses to return to a relay once a direct path has been established, accepting connection failure as the outcome if that path dies. Fastest reproduces the upstream objective and exists so the privacy preserving policies have a measurable baseline.

The blind mailbox

Direct delivery requires both peers online. On mobile devices that is the exception, so a store and forward component is unavoidable. The design goal is to make its operator's knowledge as close to nothing as routing permits.

Three implementation decisions

No length prefix. Padding is trailing zeroes, and the recipient recovers the real content because the inner MLS message is self delimiting. Writing a length field is the natural implementation and would have handed the operator precisely the information the buckets exist to remove.

Addressing is never transmitted. Both parties derive the tag key from the MLS exporter secret, so no addressing information crosses the network. The derivation must be pinned at a mutually known epoch: the exporter changes with every MLS epoch, and a sender one commit ahead of a recipient would otherwise deposit under a tag the recipient cannot compute, producing silent undeliverability.

Collection is destructive. A collected envelope is removed. A client that crashes mid collection loses those messages. The alternative is a mailbox that retains copies, which is the property being designed against.

Not enforced by the protocol

Deletion is a promise the reference implementation makes, not one the protocol enforces. A hostile operator can retain everything and no client can detect it. The mitigation is structural rather than cryptographic: the mailbox is a single self hostable binary, so compromising one operator compromises one community rather than a population.

Message padding, measured

Traffic analysis of encrypted messengers recovers user actions, message language, and message length from observed packet sizes with accuracy above 96 percent.[6] Padding is the standard countermeasure and its effectiveness is frequently overestimated: random padding can reduce attack accuracy to zero at over 300 percent bandwidth overhead, while per packet schemes reduce it to roughly 8 percent.[6][7]

An initial scheme that did not work

Rotelyx originally padded envelopes to five buckets with the smallest at 256 bytes, which appeared generous for a chat message. Measurement of the MLS layer showed otherwise.

Two findings followed. First, OpenMLS applies no plaintext padding by default: overhead is a constant 145 to 146 bytes and the remainder is one to one, so ciphertext length discloses plaintext length exactly. This matters most on the direct peer to peer path, where there is no envelope and the bucket scheme therefore does not apply at all.

Second, a 256 byte bucket accommodates barely one hundred characters after MLS overhead, so ordinary messages straddled the boundary. The scheme communicated a binary short-or-long signal to the operator on every message, which is materially worse than no padding would suggest.

The corrections were to enable MLS plaintext padding to a 256 byte multiple, which protects the direct path as well, and to raise the smallest envelope bucket to 1 KiB. Ordinary conversation now collapses into a single bucket. The cost is that a one word reply occupies 1 KiB on the wire.

A second revision, for a cost that bought nothing

The five bucket ladder survived that correction and was wrong again for a different reason. Its steps were 1 KiB, 8 KiB, 64 KiB, 1 MiB and 8 MiB, so the jump from 64 KiB to 1 MiB is a factor of sixteen. A group commit for a thousand members measures 83 KB and was therefore padded to 1 MiB: twelve times its own size, paid by every member on every membership change.

The padding bought nothing there. A commit’s size is a function of the number of members, and that number is already visible to the operator, because a fan out names every recipient. Twelve times the bandwidth was being spent to hide a quantity in plain view.

The floor did not move, which is the part that matters: every message from a one word reply to a long paragraph still lands in the same bucket, and that is the property protecting conversation.

The cost is stated rather than buried. Above the floor a length is now known to within a factor of two rather than a factor of eight. That affects files and protocol traffic, whose sizes are far less revealing than a sentence’s, and it is what makes a group of a thousand affordable at all.

Method note

Neither defect was found by review. Both were found by a cross layer test asserting that a 2 byte and a 150 byte message are the same size on the wire. The unit tests for each layer passed throughout.

Reachability and abuse resistance

Removing telephone numbers from the identity layer removes the natural scarcity that limits bulk unsolicited contact. An Ed25519 keypair costs nothing to generate and nothing to discard when blocked. This is the same property that made Kik, a username based messenger, a persistent venue for unsolicited contact.

Cryptography does not address this. Scarcity does, and only two forms are available: authorisation and cost.

Authorisation as the default

An identity is unreachable unless the caller holds an invitation it issued out of band. The caller proves possession with a MAC over its own identity and the current hour, checked against the identity the QUIC handshake already authenticated. An observed proof therefore cannot be replayed by a different caller without also stealing that caller's private key.

Revocation is distinct from expiry and is surgical: revoking a leaked invitation does not affect holders of others. Expiry is a promise about the future; a leak is a present problem.

Cost for publicly reachable identities

Identities that must accept strangers, such as a support account, may require a proof of work. The proof binds to the sender, the recipient, and the hour. Each binding removes a specific reuse strategy.

BindingReuse strategy it removes
RecipientSolving once and spending the work across an address book. The sender pays per recipient.
SenderSolving once and reusing across a fleet of throwaway identities. Each identity pays again.
HourStockpiling proofs in advance. Proofs also expire without any revocation step.

Jointly these force a bulk sender to choose between reusing one identity, which is blockable, and paying the work for every new one. The mechanism does not stop a determined individual attacker and is not intended to. It targets the economics of bulk contact.

The blocklist is consulted before any verification work, so a blocked identity imposes no computational cost on the recipient. A block that still consumes CPU is a block the blocked party can exploit.

Admission control on the relay itself

Everything above governs who may open a session with a person. A relay is a different surface: it accepts connections from endpoints it has no relationship with, and the vendored transport it derives from ships no accept-time limits at all. A relay run as published would accept connections until it ran out of file descriptors, which is a denial of service that costs an attacker almost nothing.

Admission is therefore bounded per identity and in total, and the numbers are stated here because a limit whose value is undocumented is a limit nobody can argue with:

Two properties matter more than the values. The limiter composes with whatever access control is configured rather than replacing it, and the inner decision runs first, so an identity that is not permitted is refused for that reason and never consumes a rate limit slot on the way. And a refusal is indistinguishable from any other closed connection: a relay that explained itself would be an oracle for its own policy.

The refusal counts are reported to the operator’s log and deliberately not to the public status page. A live count of open connections is a load signal, and on a relay with few users a load signal correlates with who is talking.

An address per invitation

An endpoint answering under a single key is reachable at one address for everybody, so whatever carries the traffic sees a stable name shared by all of that endpoint’s correspondents, and two people invited by the same host can discover as much by comparing what they were given. Each invitation therefore carries a transport key of its own, and the code handed to a holder is that address as well as the permission to use it.

One endpoint answers all of them on one socket and one relay connection. Two arrangements are made together, and neither is useful alone. Answering is local: the TLS certificate resolver holds every key and selects by the endpoint identifier carried in the ClientHello server name, which arrives before any key must be produced. Being found is the relay’s: the endpoint asks it to route the address to this connection, presenting a signature made with the invitation key over the pair (connection, address). Binding to the pair keeps a binding from being replayed onto a different connection, and the relay refuses an address that is already some connection’s own or already answered elsewhere. Taking another party’s address requires that invitation’s secret key.

Admission is bound to the address as well as to the permission: the endpoint admits only on the invitation answered at the address the call arrived on, so a proof issued for one address is worthless at another. The address is the one the endpoint presented, not the one the caller requested in the TLS server name. A requested name the endpoint does not hold is answered by its own key regardless, and an honest caller rejects that while a hostile one keeps the connection; reading the request would therefore let a caller select an address belonging to no invitation and escape the check entirely. Omitting that check would leave the separation observable but not testable: a holder encountering an address it suspected of belonging to the same host could dial it, present its own invitation, and learn the answer from whether it was let in.

The property obtained is unlinkability between an endpoint’s correspondents with respect to each other and to a passive observer: no two are given a name in common, nothing on the wire relates the names, and no holder can test a name it did not receive. It is not obtained with respect to the relay. All of an endpoint’s addresses are answered on one relay connection, and the relay holds the table mapping them to it, so it can see that the parties reaching those addresses reach the same host. Withholding that would require a relay connection per invitation, multiplying connections, handshakes and presence signals by the number of invitations; the present implementation does not do this. Two further limits: the routing lives in the relay’s memory, so it is re-established on reconnect but must be requested again by a fresh process, and answering at several addresses is not serving several conversations concurrently.

Groups

A conversation of two is a group of two, so groups needed no new cryptography. What they needed was a way to address them, and the obvious way is wrong.

Mailbox collection is destructive: an envelope handed over is gone. With two members that is exactly right, because a sender cannot collect its own deposit and the other side therefore gets it. With three it fails silently. A message deposited under one shared tag is collected by whichever member reaches it first, and the rest never see it.

Every member therefore has its own tag, derived from the group’s exported key and that member’s signature key. Every other member computes the same value for a given recipient and nobody outside can. A signature key rather than a leaf index, because MLS reuses a slot after a removal and the new occupant would inherit the departed member’s tag.

The cost of addressing everyone

One tag per member means one copy per member. Uploading each copy separately makes a group of a hundred unusable on a phone, so the mailbox fans out: a sender uploads once and names every recipient, and the server makes the copies.

That is a real reduction in what the operator has to infer, and it is stated rather than glossed. Before, it saw a burst of deposits and had to correlate them against who subscribes to what. Now the recipient set arrives written down in a single request. The operator could already reach the same conclusion, since it observes which connection listens on which tag, so this makes an existing inference cheap rather than creating a new one. It is the price of groups beyond a few dozen.

Padding stays on the client. The server refuses a payload that is not already a bucket size, because a server that padded on the sender’s behalf would be handed the true length, which is the one thing the buckets exist to withhold.

Post-quantum material for more than two

The composition in section 4 does not survive the move to groups unchanged. Encapsulation derives a shared secret rather than carrying a chosen one, which is right for two parties and useless for many: MLS looks a pre-shared key up by a single id, and a commit carrying different material for different members fails for all but one of them.

The committing member therefore chooses one group secret and seals it to each member individually. X-Wing protects a wrapping key and XChaCha20-Poly1305 protects the secret under it, so both halves of the hybrid still have to break for the group secret to leak. 1192 bytes per recipient, once per rotation.

Where the ceiling actually is

Not in MLS. The ratchet tree grows by about 186 bytes per member and the commit by about 83, so the largest padding bucket would hold a group of roughly forty five thousand. The limit is what a membership change costs every member: 32 KiB at 256 members, 128 KiB at a thousand. An ordinary text message costs 1 KiB at any group size, because the floor of the padding ladder does not move.

Media

Calls work, and were the largest piece of unfinished work in the project until August 2026. What decides whether a call is as end to end as a message is the keys and the frame format, and those came first; what followed was the media engineering, which is the long part and is not finished. Two processes now hold a measured conversation through a relay, and echo cancellation is still absent.

Why media cannot reuse the message layer

An MLS application message is ordered, reliable and ratcheted. Every message advances a chain, and one that arrives out of order or not at all is a problem to be resolved. Audio is the opposite: frames arrive every twenty milliseconds, some never arrive, and a frame that is late is worthless rather than worth waiting for. Fifty ratchet steps a second per speaker, stalling on every lost packet, produces a call that breaks whenever the network does.

Media therefore takes a key from MLS and does its own framing, in the shape of SFrame.[12] A counter travels in the clear so any frame can be decrypted on arrival without the frames before it, and a replay window covers the consequence of that, which is that a counter in the clear is a counter an attacker can repeat.

One key per speaker

Each participant encrypts under a key derived from the group’s exported media key and that participant’s identity. Two consequences, and the second is the one that matters. Counters cannot collide, so no nonce repeats. And a frame claiming to be from one member can only have been produced by that member: under a shared key any participant could manufacture another’s stream, which in a call means putting words in somebody’s mouth.

The key changes with the epoch, so a membership change rekeys the call. A removed member stops being able to decrypt immediately rather than at the end of the call, which is what a removal has to mean.

A codec for a channel where latency is free

Opus will not be beaten at its own objective, which is quality per bit under a hard twenty millisecond latency budget. That budget is not a detail; it is the constraint the whole design bends around, forcing short windows, no lookahead, and loss concealment inside the codec because the transport cannot recover anything in time.

Rotelyx’s fidelity channel has none of the three. Telyx is what that produces: a 40 ms MDCT window, twice the frequency resolution at the same hop; Bark spaced bands; and energy coded separately from shape, so a starved band keeps its loudness and loses only its texture.

Why the shape is coded as a vector

At 24 kbit/s a frame has roughly 336 bits left after the band energies, against 960 coefficients. That is a third of a bit each. Scalar quantisation cannot spend it: the cheapest thing it can say about a coefficient is one bit, so it says nothing about any of them. The first working version of Telyx sat in exactly that state, filling every band with noise while its entire budget went unspent.

Pyramid vector quantisation describes the band as a whole instead: a direction chosen from every way of placing K signed pulses across N positions, where the codebook size follows V(N,K) = V(N−1,K) + V(N,K−1) + V(N−1,K−1). Choosing K chooses the rate at any fraction of a bit, and the codebook is never stored, because it is enumerable.

Every codeword has the same norm, which is the property that matters for speech: a band’s loudness is carried entirely by its transmitted energy and cannot drift with how coarsely its texture was coded. Starve a band and it becomes a rough version of itself at the right level, which is the failure a listener forgives.

Residual stages, and what they actually buy

Neural codecs beat Opus by wide margins at low rates, and the part doing the work is the quantiser rather than the network: code the vector coarsely, subtract what was coded, code what remains. Nothing about that requires a learned codebook.

Measured, staging is not a better rate. Two stages of eight pulses match a 16 coefficient band to 0.989 for 60 bits, against 0.985 for a single stage of twenty four using 51. What staging buys is a ceiling that one stage does not have: V(64,16) outruns a 64 bit index, so a single stage on a wide band stops at twelve pulses and a 0.751 match, while three stages reach 0.867. The gain grows with the width of the band, and wide bands are where the upper spectrum lives.

What has not been done

Nobody has listened to it. Every number here is objective, and codec quality is not: it is settled by listening panels, and a decade of Opus’s advantage is exactly that tuning. No comparison with any other codec can be made until that has happened.

Layers, and why only this channel can use them

Residual stages are ordered by importance and independent to decode, so a frame need not arrive all at once. Telyx splits one into a base and three refinements: the base carries the band energies and the first stage of every band, and each refinement improves on the last.

For a telephone call this is worthless. A refinement arriving after its frame has played is discarded, so there is nothing to gain by sending it separately and overhead to lose. On a channel that already spends seconds of delay and already asks for lost frames again, a refinement that arrives late is a refinement that arrives.

One encode therefore serves every rate. A listener on a poor link is sent the base and nothing more; the same recording sent elsewhere carries every layer. Nothing is re-encoded and nothing is stored twice.

What it does not yet buy is a base cheap enough to protect much harder than the rest, though it is closer than it was. The twenty four band energies took eighteen bytes of a sixty byte frame at six bits each; they now take twelve and a half. Getting there took four attempts, and three of them failed in ways worth recording.

Four attempts at the band energies

The floor was measured wrong. A helper computing the entropy of the energies multiplied each symbol’s surprise by its own count rather than by the total, and reported the floor as under two bytes a frame against a true figure near fifteen. Work was then aimed at a ten-fold saving that did not exist. An error in a measurement does not announce itself the way an error in a program does; it produces a number, and the number is used.

The prediction was pointed at the wrong axis. Each band was predicted from the same band in the previous frame, which is the design anyone would write first. But the fastest-moving thing in a voice is its overall level, and twenty milliseconds is long enough for it to move a great deal, while the shape of the spectrum barely moves at all. Predicting each band from the band below it, within the same frame, took the energies from 15.4 to 12.9 bytes a frame and made every frame independent of every other. Codec 2 reached the same conclusion for its mel-spaced envelope, and cites the independence rather than the bits as the reason.

The coder was flushed fifty times a second. An arithmetic coder must be closed before its output can be read, and closing costs four to six bytes whatever it is carrying: thirty seven all-zero symbols come to six. A long stream amortises that to nothing and a 20 ms frame pays it in full. Batching ten frames into one stream pays it once, at the cost of 200 ms of latency and of tying a group’s energies together. Both are affordable here and neither is affordable on a telephone call. MELPe at 600 bit/s groups four frames into a superframe for the same reason.

The energy step was the ceiling all along. The codec saturated at 26.3 dB however many bits it was given, and the reason was not the shape coder. A 1.5 dB energy quantiser has an rms error of 0.43 dB, and a gain error of 0.43 dB predicts an SNR of 25.9 dB. Every bit above 24 kbit/s was refining a shape that was then multiplied by the wrong number. The step is now derived from the frame size, which both sides already know and so costs nothing to signal: coarse where a finer envelope would be paid for out of the shapes, fine where the envelope is the limit. That is 26.2 to 28.2 dB at 24 kbit/s, and a ceiling of 29.2 rather than 26.3.

What the low-rate vocoders had to teach us

MELP, MELPe (STANAG 4591) and Codec 2 operate between 600 and 2400 bit/s, an order of magnitude below Telyx, and most of their machinery does not transfer. They are parametric vocoders: they resynthesise speech from pitch, voicing and a linear-prediction envelope, where Telyx codes a transform of the waveform. Mixed excitation, bandpass voicing, pulse dispersion and aperiodic jitter all shape an excitation signal that Telyx does not have.

What did transfer arrived as confirmation: the superframe and the predictor above. What did not transfer is more instructive. Codec 2 found that 6 dB envelope steps cost it very little quality. The same step costs Telyx 13.7 dB of SNR, because a vocoder resynthesises from the envelope while Telyx multiplies its coefficients by it, so an envelope error is a gain error on the output waveform. A result imported without its reason would have made the codec substantially worse.

Two ideas from that literature remain unexplored and are worth the work: MELPe’s noise pre-processor, designed for battlefield noise and directly relevant to a phone in a loud room, and the analysis-by-synthesis principle from CELP, which selects the quantiser index minimising perceptual error rather than the one nearest in the parameter domain. Telyx’s residual quantiser currently does the latter.

What happened when it was given sounds it had never been given

Every figure recorded for Telyx had been measured on one signal: twelve harmonics with vibrato, a formant and an amplitude envelope. That is a sustained vowel. Speech is not made of sustained vowels, so the codec was given a plosive, a fricative and a voiced onset after silence.

The negative figures are not straightforwardly a failure, and saying why is the first useful thing the exercise produced. A fricative is noise. The codec reproduces its spectrum rather than its waveform, and two different noises with the same spectrum sound identical while scoring about zero decibels against each other. That is a demonstration, from this codec's own numbers, of why an SNR comparison against Opus would carry no information.

Three real defects did fall out, and none of them was visible to any test that already existed.

The noise fill was not noise. A band that receives no bits is given an invented texture, and that texture was a hash of the coefficient index and nothing else: the same pattern in every frame, indefinitely. A decoded fricative correlated with itself one frame later at +0.991, against +0.008 for the noise that went in. That is not a hiss but a tone at the frame rate, and 48000/960 is 50 Hz, so an /s/ emerged as a buzz. Signal to noise cannot see this; the level is correct throughout; every round trip test passed either way. The comment above the code said the signs had to be random, and they were merely scattered. Seeded from the decoder's frame counter it now measures +0.010.

A rate too low to carry the envelope was delivered rather than refused. The encoder finished a frame with a resize to the frame length, which pads and also truncates; the truncating case had never been considered. At fifteen bytes a frame the band energies alone require eighteen, so the final bands were cut off, read back out of the zero padding, and the frame decoded six decibels quiet with no error raised anywhere. It had been published as the 6 kbit/s row of the rate table.

Pre-echo is real and remains unfixed. A plosive places noise 14.8 dB below itself into the silence preceding it, because a 40 ms window spreads quantisation error across its whole length. This is the known cost of the long window and the remedy is block switching, which is not built. It is now measured and recorded rather than left to be discovered by a listener.

What systematic mutation found in the decoder

A decoder normally sits behind an authenticated transport and only ever sees what a real encoder produced. That is an argument for not testing it against anything else, and it is wrong twice: the authentication can be misconfigured, and a decoder is exactly the component that gets reused later somewhere the authentication is not there.

Every parser reachable from the wire is therefore driven with every truncation, every byte value at every position, and arbitrary input from a fixed seed. Not a fuzzer: it runs in the ordinary test suite on every change rather than in a separate tool nobody remembers to start.

It found one defect, and the class matters more than the count. A single corrupted byte in a Telyx frame decoded to a peak of 3,530, three thousand times full scale, because a band’s energy is exponential in its coded level and one byte moves it a long way. A corrupt frame is not a rare event on a real network, and in headphones that is not an artefact but a hazard to the person wearing them. The overlap-add now clamps to full scale, which costs one comparison per sample. No unit test built from valid input would have produced it.

The layers on the wire, and what it cost to find out

Giving each layer its own datagram is the obvious way to let a network drop refinements, and it was costed before it was built. Every datagram carries its own sixteen byte authentication tag, and on frames this small the tag is most of the packet.

StreamOne datagramOne per layer
12 kbit/s19.6 kbit/s on the wire42.4
16 kbit/s23.646.4
24 kbit/s31.654.4

Splitting a 24 kbit/s stream four ways puts more on the wire than the stream carries. So the layers travel in one datagram, self-delimited by a byte of layer count and a length for each layer but the last, and the sender decides how many to include before protecting the frame, which is free. The lengths sit inside the authenticated payload rather than in the header, so a flipped bit in a length field is a failed tag rather than a parse of attacker-chosen structure.

Measured end to end, a link with room for 40 byte datagrams carries 89 percent of the bytes a 96 byte link does. That is not a limitation of the trimming; it is the shape of the frame. The base layer is 86 percent of it, so discarding every refinement can save at most fourteen percent, and 44 percent of the base is the energy envelope. Layered delivery is worth what the base costs, and the way to make it worth more is to shrink the base rather than to trim harder.

The transform was the whole story

Written from its definition the MDCT is O(n²): 1.8 million multiplies and as many evaluations of a cosine per frame, 28 ms forward and 26 ms back against a frame carrying 20 ms of audio. A call needs both directions, so the transform alone cost 270 percent of real time on one core. Every quality figure in this section was, until that was fixed, measured offline on a codec that could not have carried a conversation.

An MDCT of 2M samples is a fold onto M values followed by a DCT-IV, and a DCT-IV of length M is a complex FFT of length M/2 between two twiddles. For 960 coefficients that is one 480 point transform, and 480 = 25 × 15: the factorisation halves five times and finishes with thirty two direct fifteen point transforms. The result is 0.5 percent of real time, and the whole codec, encoding and decoding together, is 1.2 percent.

It is also 775 times more accurate than the definition it replaced, which is not what a fast path usually is. Summing 1920 similar terms in single precision loses about two parts in ten thousand; an FFT accumulates in a tree of depth nine instead. That mattered practically: the fast transform was first checked against the slow one, disagreed by exactly that much, and the disagreement looked precisely like a wrong twiddle factor. A fast implementation can only be checked against a slow one while the slow one is the more accurate of the two.

A call, end to end

Until August 2026 nothing in the project made a call. The codec had been measured on files, the media layer had been tested against an in-process network, and the two had never met over a socket. They have now: two processes, real devices, real datagrams, through a running relay.

Twenty seconds of speech each way carried 991 frames sent and 944 received, with 79 milliseconds of audio queued for playback at the end and nothing discarded. At fifty frames a second that is the call running in real time rather than falling behind, which is the only property that matters and the one the first version did not have.

The first version managed 322 frames in the same twenty seconds and accumulated 360 milliseconds of delay that never came back. The cause was one line of scheduling: it encoded one frame per timer tick, and a timer that fires late does not fire twice to make up for it, so every late tick left twenty milliseconds in the buffer that nothing removed. Draining what is ready on each tick instead took it from a third of real time to real time. It is recorded here because it is invisible to every test that does not run against a clock.

A call refuses a direct path

A call will not start on a connection that permits a direct path, and the refusal is in the media layer rather than in a caller that could forget it. The reason is not latency: a direct path is the caller’s address handed to whoever is on the other end. Relay-only costs a round trip through a machine that can read nothing, and it is the difference between a call that hides where somebody is and one that does not.

The same audit found the address itself leaking. The string a user pastes to a peer is built from whatever the endpoint knows about reaching itself, which on an ordinary machine is its IP and port, and it travelled even on relay-only sessions where the peer could not use it. Relay-only addresses now carry the relay and nothing else.

Somebody listened

Every number recorded for the codec until this point was signal to noise, and signal to noise does not say whether a codec sounds good. Three clips were rated blind and in random order against the untouched original.

One clip rated 16 kbit/s below 12, inverted against both the measurement and the other two clips. It was worth checking, it did not hold up, and it is written down so that it is not rediscovered later as a finding. What would make any of this conclusive is a second listener, which is worth more than more clips from the first one.

What is not built, and what it will cost

Echo cancellation and congestion control are absent. Echo cancellation in particular is not written from scratch by anybody sensible, and without it a call on a speakerphone sends the other side back to themselves. Device capture and the jitter buffer, listed here as missing in earlier versions of this paper, are built.

One measured cost is already known. Frame overhead is 25 bytes, a nine byte header and a sixteen byte tag, which on an 80 byte Opus frame is 31 percent. SFrame permits truncating the tag to eight or four bytes for exactly this reason, and that should be done before a call runs over a metered connection.

Group calls above a handful of participants need a unit that forwards streams. The frame format already suits one, since the header is authenticated but not encrypted and can be routed by without being read. What such a unit sees is who is speaking and when, and with silence suppression that is the rhythm of the conversation. It is the same bargain the blind mailbox makes, and it should be declared before anyone builds on it.

Limitations

This section states the known weaknesses of the design. Several are unsolved and at least one is unsolvable within the current architecture.

Statistical disclosure against rotating tags

Signal's sealed sender removes the sender field from a message, and the resulting one sided anonymity is broken when two parties exchange messages back and forth. The attack belongs to the family of statistical disclosure attacks and is made substantially more effective by delivery receipts, which are enabled by default and cannot be disabled.[8] The attack has been extended from deanonymising communicating pairs to deanonymising entire group conversations.[9]

Rotelyx's rotating tags face the same class of attack, and the analysis transfers with two differences.

Two properties of the Rotelyx design change the attacker's task relative to Signal, one favourably and one not.

Favourably: Rotelyx sends no delivery receipts. The published attack is significantly strengthened by receipts that guarantee an immediate response, and their absence removes that amplification. Delivery confirmation, if it is ever added, must be treated as a metadata decision rather than a user experience one.

Unfavourably: tags rotate hourly rather than per message, so all envelopes for one pair within an hour share a tag. This is a deliberate trade for deliverability against clock skew and offline recipients, and it gives the operator a clustering key that Signal's per message sealed sender does not provide.

Unsolved

We do not claim resistance to statistical disclosure. Plausible mitigations include per message tags with a recipient side scan, randomised collection delays, and decoy deposits. Each carries a cost in bandwidth, battery, or latency, and none has been implemented or evaluated.

Push notification metadata

Mobile platforms will not permit a background socket, so waking a device requires the platform push service. Apple and Google therefore observe that a device received a wake signal and when. Content free silent pushes, jittered delivery, and decoy pushes raise the cost of correlating a push with a mailbox deposit, but none of them solves the problem, and all cost battery. This is inherent to the platforms rather than to the protocol.

Relay observation is inherent

A relay carrying a session necessarily learns which endpoint identifier communicates with which. No configuration removes this. Path selection minimises how often a relay is used; self hosting changes who holds the observation. Neither eliminates it. Relay chaining, which would split the knowledge across two operators, is not implemented.

Derived rather than original transport

The transport comprises 123,893 lines vendored from iroh, whose socket layer is itself derived from Tailscale under BSD-3-Clause and whose QUIC layer is a fork of quinn. Rotelyx owns the policy layers, has deleted the identity publishing code outright, and has replaced the path selection objective. It has not rewritten the NAT traversal or the QUIC state machine, and the defensible claim is a derived and substantially modified transport rather than an original one.

Vendoring also transfers the maintenance burden. Upstream security fixes no longer arrive automatically and must be tracked and ported by hand. In a cryptographic project this is not optional work.

Storage at rest

Identity keys are sealed with Argon2id, using 64 MiB of memory and three passes, and XChaCha20-Poly1305 with the file header bound as associated data. Key files written by earlier builds are migrated in place rather than rejected, because refusing to start would push people back to the binary that wrote plaintext.

Two limitations remain. The sealing key comes from a passphrase rather than from a platform keystore, so its strength is whatever the user chose. And MLS group state is not yet encrypted at rest, nor is there a backup format that avoids introducing a state rollback vector. Both are open items.

What it cost to make the vault usable

Argon2id at 64 MiB is expensive on purpose, and the expense is correct exactly once: when a passphrase is being checked. The mailbox server was re-deriving the same key from the same passphrase on every write, and the wake registry writes on every device registration. Measured against a running server, eight requests took 2.26 seconds, so under four a second saturated a core, and each derivation allocated 64 MiB on the way. An attacker did not need a botnet for that; they needed a loop.

A cache of derived keys fixes it, and the first version of that cache was an authentication bypass. It was keyed on the salt alone, so opening a file with the wrong passphrase found the entry cached from the right one and decrypted it. That is worth recording rather than quietly fixing: the change that removes a denial of service is exactly the sort of change that removes the check as well. The cache is now bound to a hash of the passphrase, compared in constant time, and there is a test that opens with a wrong passphrase against a warm cache.

With it, a write costs 0.4 ms rather than 265, and the derivation still happens once per passphrase. The test that pins this counts derivations rather than measuring elapsed time, because the timing version failed under parallel load and a flaky test is deleted the first time CI is busy.

Calls are new, and thinly measured

A call has been carried end to end between two processes through a relay, and the figures in section 10 come from that run. They are one run on one machine over a loopback relay. Nothing here has been measured across a real network, under real loss, on a phone, or on a battery.

There is no echo cancellation. A call on a speakerphone sends the other side back to themselves. Until that exists, calls are for headsets.

The perceptual measurement is one listener rating three clips. It supports the claim that the codec is usable at 12 kbit/s and it does not support any comparison between the rates, because the spread within a rate is larger than the gaps between them. A second listener is worth more than more clips from the first.

Client trust boundaries differ

Three clients exist and they do not offer the same guarantee. The desktop client uses in process IPC, so plaintext never crosses a socket. The browser harness speaks to a local process over loopback, which admits anything on the machine that can reach that port. The command line client holds everything in one process.

The harness is labelled as such in its own interface. Documenting the difference matters more than removing it: a project that ships several clients and describes them all with one security claim is making a false statement about at least one of them.

Defects found by testing rather than review

Three classes of defect survived code review and were caught only by tests that crossed a layer boundary or used real sockets. We record them because the pattern is more useful than the individual bugs.

  1. Absent padding. MLS applied none by default, so plaintext length leaked exactly. Section 7.
  2. Silently discarded data. A QUIC send stream dropped without an explicit finish resets, discarding data the sender's write call reported as successful. Write then drop is the obvious usage pattern and it lost the final message of every session with no error anywhere.
  3. Unreachable policy types. On three separate occasions a type documenting a security guarantee was never consulted by the code path it was supposed to govern. The path selection policy, the reachability policy, and the post quantum commit function each compiled, passed their unit tests, and enforced nothing.
Observation

The recurring failure is not incorrect logic but unreached logic. Unit tests confirm that a decision function returns the right answer; they do not confirm that anything asks it. Every security control in Rotelyx now has a test that exercises it through the surface a real caller uses.

What ships, and whether it can be checked

A protocol that asks people to trust no server still asks them to run a binary. Two properties of those binaries were wrong, and both were invisible until somebody looked at the bytes.

They carried the build machine’s username. Rust embeds file!() in panic messages, and for a dependency that is the full path into the build machine’s package registry. Measured before it was fixed: 173 such paths in the WebAssembly module downloaded by every visitor, 387 in the relay and 269 in the mailbox server. That is the operator’s account name, shipped to strangers, in a project whose entire subject is not revealing who somebody is. Paths are now remapped at build time, and the build refuses to produce an artifact that still contains one.

The same change made the builds reproducible, which is the more valuable half. Two clean builds of identical source produced different bytes before and produce identical bytes now. Without that, publishing source alongside a binary is a claim nobody can test: an operator running a relay somebody else compiled had no way to establish that it corresponds to the source it claims to come from. The hashes are printed by the build and can be published beside the artifacts.

The browser module also shrank from 2,352,899 bytes to 1,510,029, and from 749,195 to 531,303 compressed, by choosing a size-optimised profile and dropping the debugging symbol names. Production stack traces become numeric, which for a client that handles keys is arguably the better default anyway.

Conclusion

Rotelyx demonstrates that a messaging protocol can treat metadata as a primary design constraint without inventing new cryptography. The three mechanisms that carry that claim, hybrid post quantum injection at a standard extension point, an inverted path selection objective, and a mailbox that observes only an opaque tag and a bucketed payload, are each small, each independently testable, and each accompanied by a statement of what they do not cover.

The most important limitation is section 9.1. The mailbox reduces what an operator can read to nothing and reduces what it can identify to a correlation problem, but it does not solve that correlation problem, and the published attacks against Signal's sealed sender apply. Claiming otherwise would place this work in the category of systems that assert unbreakability, and those claims have been false every time they have been made.

The work required before any public security claim is a full independent cryptographic audit covering the post quantum composition and the implementation of both encryption layers. Until then, Rotelyx is a design with a working implementation and no verified guarantees.
